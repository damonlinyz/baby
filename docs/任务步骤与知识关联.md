# 任务步骤与知识关联

网页、HTML5+ 共用页面和微信小程序现在可以在新建或编辑任务时填写执行步骤、选择关联生活知识。步骤是按顺序阅读的说明，不自动打卡，也不代替任务完成及妈妈确认。

## 输入与协作权限

- 最多 12 条步骤，每条最多 200 字，服务端去除首尾空白，拒绝空步骤、非法类型或超长列表；客户端按每行一条录入。
- 最多关联 5 篇不重复的当前已发布、未过期、非医疗生活知识。仅保存知识 ID，不把旧知识正文复制进任务；阅读时显示当前版本与来源。
- 统筹者编辑步骤和关联。其他成员按原任务查看范围阅读步骤、打开引用；普通成员仅可查看自己负责的任务。执行状态仍由执行人提交，内容编辑不等于执行完成。
- 编辑待确认任务时使旧确认和未读确认提醒失效，回到进行中，由执行人重新提交；旧版本表单拒绝覆盖别人的修改。现有任务的完成、撤销与报告口径不变。
- 网页与小程序编辑均保留打开表单时的版本。关闭、退出、会话失效或回到前台重新核对授权时清理任务草稿与详情。

## 关联阅读与下架

状态和可见数据导出只返回当前可用的关联 ID 和标题/来源/版本元数据。内容撤回、过期、改为医疗内容后，从关联区域移除；既有用户自行填写的步骤不当作知识正文，也不伪称随下架自动删除。

通过 `GET /api/task/knowledge?family_id=...&task_id=...&knowledge_id=...` 阅读引用。服务端在同一事务复查：

1. 当前有效会话和成员关系；任务属于本家庭且调用人仍有查看权限。
2. 健康日期任务具备当前健康查看授权，宝宝任务另具独立宝宝授权；普通成员仍是当前任务负责人。
3. 知识仍关联于该任务，且仍是已发布、有效、非医疗内容。

引用被移除或下架时拒绝旧入口，不用弹层里的旧正文交付。客户端以普通文本显示步骤、标题和来源；不会执行其中的 HTML 或把它当成写操作。响应沿用服务端禁止缓存策略，账号删除不新增需要额外清理的详情缓存。

## 重复任务

`task.create`、`task.update` 和 `task_series.update` 增加可选字段：

```json
{
  "steps": ["先盘点已有用品", "再核对实际缺口"],
  "knowledge_ids": ["base-1"]
}
```

传空列表可以清除；更新省略时保留原值。重复规则的步骤和关联复制到每个独立实例；修改规则按第十八轮的保护条件更新今天起未开始的自动实例。某次单独修改步骤或关联后，作为单次调整保留，不随后续整组改写。暂停、规则关闭和停止的实例保持只读。

## 生活模板内容与来源

新家庭的四项初始任务，以及新生成的 22 项孕期/产后生活模板，增加明确的步骤和来源。使用模板内容版本 2，来源标记为“产品编辑 · 一般生活事务模板”；已有任务不会因版本升级批量覆写，尤其保留已完成和已手动修改的内容。

模板按陪伴、资料准备、家庭协作、物品准备、出行准备、生活准备六类组织，分别强调倾听与明确分工、向实际机构核对要求、盘点现有物品、核对交通信息及按实际精力整理空间。引用只选当前有效的生活知识。模板不新增检查时间，不推断医疗行为，也不把一般生活步骤描述成专业医护意见。

任务展示“原模板来源”，自行修改步骤或关联后额外标注已修改，避免把自填内容当成未经改变的编辑模板。模板的日期锚点、敏感授权、暂停和宝宝安静处理沿用原有规则。医疗模板与内容审校属于独立的外部验收范围。
