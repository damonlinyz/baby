# 自用数据库备份与恢复

工具：`backend/maintenance.py`。命令在仓库根目录执行，使用 Python 标准库。加密任务、保留周期、定时器模板和状态检查见 [加密备份与自动任务](备份自动任务.md)。

## 文件与一致性

首次启动新版服务会为数据库写入随机实例标识，并创建独立删除记录文件：

- `private/baba.sqlite3`：业务数据库。
- `private/baba.sqlite3.deletions.sqlite3`：删除墓碑，仅保存随机账号 ID 与删除时间，不保存健康原文。

账号删除与墓碑在同一 SQLite 附加数据库事务内提交；要求两份数据库使用 `DELETE` 日志模式，不支持改为 WAL。删除事务失败时，两边一起回滚。上述路径均已由 Git 忽略规则排除。

业务快照与删除记录分开保管。恢复旧业务快照时必须使用**当前最新的、同实例的删除记录**。用旧删除记录替代最新记录会丢失后续删除事实，工具无法凭空重建；因此删除记录需要独立持续备份，不能与旧业务快照一起回滚。

## 创建快照

先运行一次新版服务完成初始化。正常运行时可用 SQLite backup API 创建一致快照，不直接复制正在写入的数据库文件：

```sh
python3 backend/maintenance.py backup --db private/baba.sqlite3 --output backups/baba-20261022.sqlite3
python3 backend/maintenance.py backup --db private/baba.sqlite3.deletions.sqlite3 --output backups/deletions-20261022.sqlite3
python3 backend/maintenance.py check --db backups/baba-20261022.sqlite3
```

文件名自行更换。工具拒绝覆盖已有文件；成功输出 SHA-256，可用于传输前后核对。输出权限为 `0600`，执行 SQLite 完整性和外键检查。文件未加密，应放入你控制的受限存储；不要上传 Git。

## 恢复到独立文件

停止服务及其他写入进程，保留当前原文件；使用最新删除记录生成新的恢复文件：

```sh
python3 backend/maintenance.py restore --backup backups/baba-20261022.sqlite3 --ledger private/baba.sqlite3.deletions.sqlite3 --output private/recovered.sqlite3
python3 backend/maintenance.py check --db private/recovered.sqlite3
```

工具同时生成 `private/recovered.sqlite3.deletions.sqlite3`，保留删除历史供后续恢复继续使用。不会覆盖现有输出文件，不会自动替换正在使用的数据库。

恢复会重放快照之后的账号删除，清理关联健康日期、任务、确认与提醒；旧会话全部失效，共享授权和未用邀请撤销，待接受转交与待确认请求取消，历史命令结果失效。每位家人需要重新登录，由资料本人重新授权。

若被删除账号在旧快照中还是统筹者，恢复会拒绝输出并提示选择统筹转交之后的较新备份。工具不会猜测接任人。缺少删除记录、实例不匹配或完整性检查失败也会拒绝恢复。

核对家庭、任务与权限后，用新路径启动：

```sh
BABA_DB=private/recovered.sqlite3 PYTHONDONTWRITEBYTECODE=1 python3 backend/server.py
```

测试过程使用另一端口时需同时配置 `PORT` 和 `PUBLIC_ORIGIN`。不要将恢复后的旧订单状态直接视为支付渠道当前状态；启用真实支付/付费 AI 前需要单独对账，当前工具不提供渠道对账能力。

## 已验证与待办

合成数据自动演练覆盖：快照后删除健康资料本人、恢复后无原资料、旧授权失效、墓碑继续保留、删除事务回滚、损坏数据库/错误删除记录拒绝、已有文件不覆盖、旧统筹者删除后拒绝过旧快照。第十二轮另补充加密备份与独立删除记录解密恢复，验收记录见开发任务清单。

定时任务模板、加密快照、独立高频删除记录、保留周期和本机失败/过期检查已提供。生产定时器、异地保存与外部故障通知尚未配置；可执行工具和合成演练不代表已有运维服务。
