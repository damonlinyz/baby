# 多端弱网重试与授权复核

第十三轮将网页、HTML5+ App 共用页面与微信小程序的家庭修改接到同一份请求恢复模块：`clients/weapp/lib/recovery.js`。网页由后端白名单路径 `/request-recovery.js` 加载，小程序直接 require，不需要复制两套逻辑。

## 本轮行为

| 场景 | 客户端处理 |
|---|---|
| 读取请求断开、返回异常或服务端 5xx | 最多自动重试一次，不缓存成功响应 |
| 家庭 `/action` 提交后响应丢失 | 用完全相同的请求号和参数最多重试一次，服务端重放原结果 |
| 已收到保存成功，但之后刷新失败 | 保留原请求号，显示“核对上次提交”，不会将再次点击当作新创建 |
| 两次自动尝试都没有确定结果 | 保留当前会话内的待核对请求，允许明确核对；阻止另一笔参数不同的家庭修改 |
| 多个相同家庭修改并发触发 | 合并为同一次请求与刷新流程 |
| 返回 400、403、409、429 等明确拒绝 | 停止自动重试；权限和版本冲突会复查状态，旧预览需重新生成 |
| 切换账号、服务地址或重置会话 | 丢弃旧会话的迟到结果，不在新会话继续重试旧请求 |
| 同一账号两次状态读取乱序返回 | 只应用最近发起的那次读取，旧响应不能覆盖较新的授权结果 |

普通请求单次超时为 15 秒；AI 单次为 90 秒。自动重试之间只等待 250 毫秒，没有无限重试。原有 AI、订单、登录、建家庭、加入、知识发布、退款等普通 POST **没有加入自动重试**；它们不属于此次家庭命令恢复范围。预览 POST 也不会自动重试。

“核对上次提交”会再次发送原请求号，由服务端按当前账号、成员和相应权限判断，再读取最新家庭状态；客户端不自行把旧结果视为仍可操作的授权。邀请的响应若在核对时取回，界面会展示原邀请码，而不是悄悄再生成一个。

## 回到前台与登录失效

- 网页可见性恢复、浏览器历史恢复，以及 HTML5+ 的 `resume` 事件会复查家庭状态；小程序 `onShow` 在首次加载之后执行同样的复查。已有提交执行中时，等待当前流程结束再复核。
- 重新读取前关闭旧弹层和预览；读取失败时清除旧家庭视图，显示重新获取入口。成员已被移出时可返回家庭选择入口；有待核对修改时须先核对，不直接换家庭重发。
- 服务端返回 401 后，网页清除账号、弹层、旧侧栏信息及待核对请求，回到登录页；小程序同时清理内存与本机保存的会话 Token、CSRF 和家庭选择。
- 较旧账号的 401 不会把后来登录的新账号退出；较旧的成功响应也不能把旧健康记录写回当前界面。

这不是服务端消息推送。授权撤回仍以服务端后续访问鉴权为准；页面持续停留时不会凭空收到撤权事件，已经保存的截图或外部副本无法追回。

## 请求保留边界

待核对参数和原请求号仅保留在当前进程内存，不写入 localStorage、小程序存储或离线队列。用户仍可明确退出账号；已经发出的请求可能已在服务端完成，退出不是撤销操作。

关闭页面、重启小程序或杀掉进程会丢失这份内存状态。重新进入时应先看服务器最新记录，再决定是否提交新操作；本轮不承诺跨重启恢复，也不会在下次登录后自动补发旧的健康操作。服务端原有版本、权限和幂等校验继续生效。

## 自动验证

完整 Python 回归包含客户端检查入口；新增客户端场景也可以单独运行，不需第三方 JavaScript 依赖：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests
node tests/client_recovery.test.cjs
node tests/client_adapters.test.cjs
```

第十三轮验收时完整回归为 167 个 Python 测试入口，其中新增入口运行 23 个 Node.js 场景；后续累计结果见开发任务清单的最新轮次。客户端场景包含真实小程序源码在模拟 `wx.request` 下的运行，覆盖结果丢失、重复提交、刷新失败、请求号保留、401 清理、账号/服务切换、前台复核与读取乱序。这不等于微信开发者工具编译或小程序真机网络验收。

浏览器验收脚本已纳入仓库：

```sh
python3 tests/run_browser_recovery.py
```

需要预先安装 Node.js Playwright 包及 Chromium；Playwright 不属于运行后端的必需依赖。独立安装的包可通过 `NODE_PATH` 指定模块目录，系统浏览器可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定可执行文件。在必须关闭浏览器沙箱的受限测试容器中，可显式设置 `BABA_TEST_CHROMIUM_NO_SANDBOX=1`；默认保留浏览器沙箱。

脚本始终创建临时 SQLite 数据库和只监听本机的随机端口服务，使用合成账号，关闭支付与 AI 销售开关，不使用应用现有数据库。运行结束清理服务和测试库。覆盖：

1. 服务端创建成功后刻意丢掉响应，自动重试仍只有一个任务。
2. 保存响应成功、之后两次状态读取失败，核对时复用原请求号，任务不重复。
3. 连续两次丢掉已提交响应，改变表单内容不能偷偷创建第二条；明确核对后恢复。
4. 妈妈撤回健康查看授权，回到前台后旧时间轴弹层关闭，日期从可见页面移除。
5. 人为延迟同一账号较早的健康快照，较新的撤权快照先返回；旧快照被丢弃。
6. 会话失效后登录页出现，旧弹层、家庭名称与草稿不再显示。

独立临时库的 Chromium 执行通过，无未处理页面 JavaScript 异常；预期的断网错误用于制造故障场景。已有时间轴分娩、误录补偿、多胎状态、单独授权、预约和管理员内容管理网页回归也通过。
