# 开发任务清单

更新日期：2026-10-28。依据产品方案 v1.3、渠道补充和当前代码；完成标准以实际测试与验收为准。

## 当前判断

已有可运行的 Python/SQLite 后端、网页、小程序源码与 App 入口。账号、家庭协作、健康授权、清单、预约和支付领域代码已存在。当前测试覆盖部分关键流程，不能据此认定完整方案交付。优先完善家庭自用的可靠性，再扩展内容、商业化与发布。

## 本轮完成：确认流程可靠性

- 确认过期时，将版本仍匹配的待确认任务/物品恢复为进行中，可重新提交；读取家庭状态和后台调度均执行过期整理。
- 模板重排仅在实际日期变化时修改任务；改期取消旧确认并恢复进行中。暂停等不改变日期的事件不会使确认因版本变化失效。
- 确认策略改变时取消旧待确认申请，相关事项恢复进行中；审批时校验策略版本、事项版本与待确认状态。
- 单独修改家庭名称不增加确认策略版本；敏感日期任务审批时重新检查查看权限。
- 新增三项领域回归测试，完整测试共 22 项通过；网页与支付适配器 JavaScript 语法检查通过。

## 第二轮完成：删除、撤权与并发可靠性

- 网页设置与未加入家庭的欢迎页增加删除账号入口，输入密码并确认删除范围后提交。仍担任任一家庭统筹的账号必须先完成转交；服务端同步校验。
- 删除健康资料本人账号时，清理孕次、关联预约、宝宝记录、敏感日期模板任务、确认和提醒；普通家庭任务解除孕次关联，家庭仍可读取且调度器不再访问悬空记录。会话随账号删除失效。
- 查看权限撤回后，代录人也不能继续读取自己录入的预约；导出、孕次列表、敏感任务、确认和提醒均按当前权限过滤。预约修改单独检查代录授权；调度器发送前复查查看权限。
- 统筹转交只保留最新待接受申请，接受前校验发起人仍是当前有效统筹；成员离开或被移除会取消相关转交与确认。转交完成撤销旧统筹代录授权与未使用邀请，新统筹不会自动继承健康授权。
- 普通动作请求使用独立的 `command_requests` 表，绑定请求号、家庭、动作和参数摘要；相同内容重试返回原结果，内容冲突返回 409。旧版未保存绑定信息的请求号返回 409，客户端可刷新后以新请求号提交。
- 删除资料时清除受影响家庭的命令缓存结果，同时保留去重标记，防止重试重建已删除数据；这些历史请求再次提交返回 409。
- 新增 15 项测试，包含两个线程同时创建任务重试、同时接受转交，以及 HTTP 撤权导出、删除与会话失效；完整 37 项测试通过，网页 JavaScript 语法和差异空白检查通过。尚未进行浏览器交互或小程序/App 真机验收。

### 当前边界

本轮清理活动数据库里的上述资料与引用；订单权益账本和必要业务审计保留。第五轮已补充删除重放与合成恢复演练；旧快照文件自身仍需按保留策略管理。其他客户端已加载的页面与自行保存的数据无法通过服务端读取鉴权追回。微信登录自动创建的账号尚无密码自助设置，因此本轮密码删除入口主要服务于账号密码用户。

## 第三轮完成：统一日期计算与变更预览

- 增加 `backend/dates.py`，使用家庭 IANA 时区（默认 Asia/Shanghai）和日历日期计算孕周、内容阶段、产后日龄与宝宝月龄。0 周有效，负孕龄拒绝；超过预产期不自动分娩。周岁按日历周年计算，2 月 29 日在非闰年以 2 月最后一天作为周年日。
- 网页与小程序统一使用服务端返回的 `pregnancy.timeline`，不再分别计算孕周；严格校验日期格式与 EDD 来源。
- 增加 `POST /api/pregnancy/preview`，校验当前成员、健康查看与代录权限；在数据库保存点内模拟变更并回滚，不保存任务、通知、宝宝或审计副作用。
- 网页与小程序保存时间轴变更前先展示新增、改期、取消待办和取消提醒的数量与明细，并说明保留的已完成记录与固定预约数。确认提交携带预览指纹；预览后家庭数据发生变化时返回 409，需重新预览。
- EDD 重排取消旧日期的未读任务提醒；分娩或妊娠结束取消孕期待办时同步使其待确认申请失效，保留已完成和已跳过历史。
- 完整 51 项自动测试通过，含日期边界、只读预览、并发预览失效、通知取消与 HTTP 保存流程；网页和小程序 JavaScript 语法检查通过。使用 Chromium 与临时合成账号验证了网页登录、服务端孕周显示、只读预览和确认保存；小程序真机尚未验收。

### 兼容与剩余范围

旧客户端仍可直接提交原有 `pregnancy.event`，新网页与小程序均走预览确认流程；预览指纹不是强制旧客户端升级的接口条件。第六轮已补充 LMP 原始日期与 EDD 估算；第十轮已补充误录分娩补偿、多胎不同结局和家庭时区修改；不据此认定全部生产场景已经验收。

## 第四轮完成：预约提醒与内容版本管理

- 网页与小程序提供预约编辑、改期、完成、取消；仍由录入人且具备当前代录授权的账号修改，版本冲突返回 409。
- 预约与任务提醒使用安排修订号去重；改期、重新打开、分工改变时取消旧未读提醒并为新安排建立独立去重键。完成和关闭普通任务提醒会取消相关未读提醒。
- 调度器按家庭时区处理当天及将到期安排，不补发已经过期的预约/任务；暂停后已取消的预约提醒不会因恢复重复发送。一般家务提醒不因缺少健康查看授权而隐藏，敏感日期提醒继续鉴权。
- 系统管理员在网页协作设置内管理生活知识的草稿、发布、撤回、到期日；每次保存保留独立版本，普通家庭统筹没有系统内容管理权限。
- 有效期包含截止当天，过期/撤回/医疗或格式无效的内容不进入列表和 AI 检索。模型无有效参考时不调用；交付与缓存重放前复查引用版本，撤回时拒绝旧答案且释放生成用量。
- 完整 64 项自动测试通过；JavaScript 语法检查通过。Chromium 验证覆盖预约编辑改期、管理员发布与撤回。真实模型、外部推送、小程序真机尚未验收。

## 第五轮完成：备份工具与删除重放

## 第七轮完成：AI 请求恢复与交付检查

- 模型请求号绑定当前家庭和问题摘要；处理中重试不重复调用，成功重试复用结果，冲突返回 409。旧版无绑定缓存要求新请求号。

## 第九轮完成：支付退款核验与幂等恢复

- 新订单绑定服务端应用与收款主体，金额由服务端商品生成；回调继续验签，并核对订单绑定。微信主动查单补充 AppID 检查，支付宝金额转换拒绝小于一分的精度与非有限数。

## 第十轮完成：误录分娩补偿、多胎状态与家庭时区

- 本人可对尚无后续宝宝状态记录的误录分娩发起补偿事件：必须明确确认、填写说明并绑定最新原始分娩事件。保存原事件、宝宝和已完成记录，将误录宝宝标记为已纠正，取消未完成产后模板；只恢复被原分娩自动取消的孕期模板，手动取消项保持原样。纠正后普通提醒先暂停，由本人主动恢复。
- 再次分娩使用新的宝宝 ID，恢复由误录补偿取消的产后待办；已完成、已跳过与手动取消的历史不覆写。缺少原始分娩事件的旧数据拒绝自动补偿，不猜测或删除历史。
- 分娩时可由本孕次本人以监护人身份逐个确认成长中、住院照护中或已离世；未单独确认的宝宝保持待确认，兼容旧客户端。宝宝也可单独修改称呼、出生日期、状态与生效日期，保留独立事件。纠正离世误录须再明确确认并填写说明，已有宝宝后续记录时不能把整个分娩改为尚未发生。
- 任一宝宝待确认、住院或离世时，不生成或取消成长、纪念类未完成自动任务；妈妈继续处于产后阶段，保留休息与家务支持。已取消的纪念任务不因普通状态变更自动重新激活；只有此前尚未生成的模板或误录补偿取消的模板可在确认后生成、恢复。
- 宝宝查看共享使用独立 `baby_read` 授权与监护人声明；健康查看或健康代录授权不会自动授予宝宝记录与编辑权限。宝宝模板、提醒、确认和导出均重新鉴权；删除本人资料与恢复删除重放会清理宝宝事件。这里的监护人声明由用户自行确认，系统没有验证法定监护资格。
- 网页与小程序补充上述编辑、只读预览和确认入口。网页孕次历史与导出保留补偿记录，宝宝事件可在有权查看的导出中读取。预览不保存任何业务副作用，并在确认时校验版本与家庭变化指纹。
- 家庭设置增加 IANA 时区，按家庭时区重新计算今日和提醒窗口，保持原始日期不变；拒绝产生未来出生、未来宝宝状态日期或负孕龄的时区。启用确认后变更时区必须由妈妈确认，确认时再次检查日期；变更重置旧未读提醒、使旧待确认请求失效。家庭名称、规则和时区一并保存。
- 完整 135 项自动测试通过；网页、小程序 JavaScript 与支付适配器语法检查通过。Chromium 使用临时数据库与合成账号验证分娩双胞胎、误录补偿、再次分娩、单个宝宝状态、单独共享及撤回、时区保存，并复查预约编辑与管理员内容发布撤回；没有真实支付、模型调用或外部消息发送。

### 本轮可复验的网页流程

1. 注册两个合成账号，创建家庭，邀请妈妈；妈妈独立建档并录入预产期。
2. 时间轴选择“记录分娩”、数量 2，逐个选择状态并勾选监护人声明；预览前后的实际记录不变，确认后显示两个独立宝宝与妈妈产后阶段。
3. 选择“纠正误录分娩”，确认实际尚未分娩并填写说明；预览显示恢复、取消项，确认后原宝宝显示已纠正，提醒暂停，原始分娩历史仍可查看。
4. 再次记录分娩，产生新的宝宝记录；在家庭空间仅将其中一个宝宝改为已离世，预览并确认后另一个状态不变、妈妈仍处于产后、未完成纪念任务取消。
5. 在隐私授权中单独开启宝宝共享，统筹者可读取宝宝；关闭后下一次状态及导出不再返回宝宝或宝宝事件，健康授权不跟着改变。
6. 统筹者设置 Asia/Tokyo，确认保存后家庭时区变化，已录入的出生日期保持原值；二次确认模式下另用自动测试核对待审批及批准时重新校验。

小程序与 HTML5+ App 真机尚未验收；外部渠道接入和部署运维不在本轮完成范围。

## 第十三轮完成：多端家庭命令恢复与授权复核

- 网页、HTML5+ 共用页面和微信小程序复用同一份请求恢复模块；家庭 `/action` 在丢响应、5xx 或异常响应时最多重试一次，复用原请求号和原参数。相同并发提交合并，未知结果未核对前阻止不同参数的家庭修改。
- 保存成功但刷新失败时保留原请求号，并提供明确的核对入口；核对后取回原结果与最新状态，不因再次点击新建重复任务。邀请码等一次性返回值也能取回显示。
- GET 最多重试一次，权限、冲突和限流等明确拒绝不自动重试。普通支付、AI、登录、建家庭等 POST 保持原有提交方式；没有自动重发离线健康队列。
