# 待产清单维护

网页、HTML5+ 共用页面和微信小程序支持物品的创建、编辑、软删除和恢复。

## 内容与权限

- 统筹者可编辑名称、备注、负责人、数量（1—100 整数）、分类（妈妈入院包 / 宝宝用品包 / 证件资料包）和优先级（必备 / 建议 / 可选）。优先级用于个人整理，不代表医疗或采购建议。
- 每个人只能提交自己负责物品的执行状态。不能在同一次请求中更换负责人并替新负责人提交完成。普通成员只能看自己负责的物品；妈妈可以查看家庭清单，内容和分工仍由统筹者维护。
- `item.create`、`item.update` 使用上述字段；更新携带 `id`、`version`。非法数量不截断、不转换成整数，返回 400；旧版本返回 409。客户端保留打开编辑时的版本，冲突后刷新再重新编辑。
- 修改待确认物品的任何内容或分工，会取消旧确认和相关未读提醒，返回进行中。需要执行人再次提交，妈妈确认的是新版本。
- 修改已备齐物品的内容或分工，会清空当前完成时间并回到待准备，避免增加数量后仍显示已备齐。纯粹保存相同内容保留原状态、版本和待确认申请。其他执行状态保持原样。
- 全确认模式下，非妈妈执行人的备齐操作进入妈妈确认；其他模式按原有规则直接更新。

## 删除与恢复

统筹者通过 `item.delete` 和 `item.restore`，携带物品 `id`、`version` 操作。删除为可逆的软删除，保存删除操作者和时间；记录仍属于原家庭。它不替代账号删除流程。

删除会取消未处理确认及相关未读提醒。已删除物品不出现在 `items`、首页进度及文本清单导出中；仅统筹者可在 `deleted_items` 查看并恢复。有权查看的完整 JSON 数据导出保留其已删除区域，用于核对和恢复历史。已删除物品不能直接修改或提交完成。

恢复不会重新启用旧确认：待确认物品删除时回到进行中；其他状态保留。恢复界面显示并可重新选择负责人。原负责人已离开家庭时，必须明确选择有效成员，服务端不会自动转交；恢复时可携带 `assignee`。已完成物品更换负责人恢复时回到待准备，不把原执行人的完成记到新负责人名下。

家庭命令使用原有请求号去重；丢响应重试不会重复删除或恢复，也不会用旧请求重放撤销后来的操作。

## 验证

本轮新增 14 项领域回归与 4 项小程序适配器场景。完整回归及浏览器结果见[开发任务清单](开发任务清单.md)。小程序代码与模拟适配器已验证，微信开发者工具和真机验收仍待完成。

浏览器验证在临时数据库和本机随机端口运行，不调用真实支付、模型或通知服务：

```bash
python tests/run_browser_bag.py
```

需要 Node.js 和可用的 Playwright Chromium。非标准安装位置可配置 `NODE_PATH`、`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`；受限容器可单独启用 `BABA_TEST_CHROMIUM_NO_SANDBOX=1`。此选项只影响验收启动，不改变生产服务配置。
