# 足迹与徽章体系 v1

适用范围：每个账号在当前家庭内的个人参与记录。爸爸、妈妈及其他家人使用同一套条件；徽章仅本人可见，不形成家庭成员之间的比较。本版包含四组、15 枚徽章，其中一枚为可选纪念卡。

## 设计目标与视觉

把“我参与了什么”变成可核对的记录，不评价谁是合格父母，也不拿生育或健康结果作成绩。四条路径可以独立进行，无需集齐；没有积分兑换、抽奖、排行榜、百分位或补签收费。

使用现有暖白、鼠尾草绿界面，圆形符号章承担识别：起步用“芽”，持续分担用“叶、树、林”，准备类用“袋、箱、册”，共同参与用“手、心、伴”，打卡用“迹、周、月、日”，纪念用“纪”。已达成使用浅绿色，未达成使用灰绿与数字进度。网页自适应网格、小程序两列卡片；不以金银等级评判家人。

安静模式使用中性配色，保留事实标签，没有火焰、音效、弹窗或庆祝动画。任何人都可主动关闭纪念与庆祝，不需要填写原因；早产等需要额外照护的情况也可直接使用这个开关。可见的暂停、归档、妊娠结束，或当前孕次中可见宝宝待确认、住院、离世时，自动使用安静模式。隐藏的健康或宝宝状态不影响其他人的开关，避免从界面变化推断隐私。

“资料”“家务”“陪伴”采用任务的既定分类与物品包分类，不从标题猜测医疗行为。普通任务和重复实例都可以贡献；同一实例重复点完成不累加，独立日期的不同实例可以分别计入任务数量，但不会自动变成连续打卡天数。

纪念卡不设集齐要求、不构成健康判断，不应催促任何人分享宝宝资料。健康查看授权不能替代独立宝宝授权；旧版自动写成成长中的记录，缺少明确监护人确认事件时不猜测补发。

## 什么算完成

- 执行人提交完成且无需确认时，在同一事务写入完成归属凭据；需要妈妈确认的事项，批准后才写入。
- 凭据只记录事项引用、执行人和完成时间，不复制标题、健康日期或知识正文。批准人不会代替执行人获得贡献。
- 每个任务或物品只有一份当前完成凭据。撤销、删除、物品内容重开或授权收回后，按当前可见事实重新核对；再次完成更新原凭据，不能靠来回点击刷次数。
- 完成后重新分工不把原执行人的贡献改记给新负责人。用户只有当前查看权限时才可使用该事项的凭据，其他人的徽章数量不返回给调用人。
- 旧完成记录缺少可靠执行归属时不从当前负责人推断，页面提示未猜测补发。已有凭据明确属于别人的记录，不误标成“旧数据缺证”。

这是应用内记录与确认流的证据，并非对线下行为的独立鉴定。陪同由本人明确声明，且关联当前有效预约版本；预约修订后需要重新核对。它不证明就诊结果，也不要求上传医院材料或健康证明。

## 打卡与连续记录

“记录今天的参与”需要本人确认当天参与过一件家庭小事。日期取服务端家庭时区的今天，不接受客户端指定过去或未来日期；同账号、家庭、日期只记录一次。登录、打开页面和完成一批未来任务都不会自动填满打卡日历。

最长连续天数按当地日历日期相邻计算，不用固定 24 小时秒数。今天尚未记录时，昨天结束的连续记录仍显示；中断超过一天后当前连续数自然归零，历史最长及已达到的连续徽章保留。没有断签羞辱，也不倒扣累计天数。不同家庭独立计算，不把多个家庭同一天的参与叠加。

## 修正、隐私与分享

徽章由当前有权查看的证据动态核对，没有不可纠正的永久荣誉账。撤销操作、资料删除、版本更正或授权变化可能调整进度；不弹“失去徽章”的惩罚文案。其他已完成事实不因一个纪念状态改变而清空。

徽章和打卡不进入通用模板或私密物品分享。不主动广播到家人群，不用分享换取解锁。账号删除清理打卡、个人归属与陪同记录；敏感事项删除同时清理其引用凭据，备份删除重放遵循同样规则。

实现：`backend/engagement.py` 的版本化目录与规则；网页“足迹与徽章”，小程序首页/家庭空间同名入口。没有接入真实推送、支付或数据排名服务才能达成徽章的条件。
