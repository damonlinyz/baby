# 重复买断收款与退款处理

更新日期：2026-10-22。适用于每个家庭一次买断的核心产品；普通 AI 续费不按重复买断处理。

## 触发场景

一笔旧订单过期后，家庭创建并支付了新订单，旧订单随后也收到渠道成功结果；或不同渠道的两笔买断收款先后/同时确认。前端限制再次下单不能消除这些情况，因此必须在服务端结算时处理。

## 结算规则

1. 照常验证签名、金额、订单应用、收款主体和渠道交易号。只有可信的成功收款才能进入结算。
2. 同一事务中查询该家庭现有有效核心权益。没有时正常授予核心产品与待激活赠送 AI；已经存在其他来源订单权益时，第二笔标记 `fulfillment_status=duplicate_core`。
3. 重复订单保留 `paid` 资金状态、真实交易号和收款时间，并引用原权益来源订单。它不生成新的核心或赠送 AI 权益。
4. 使用订单派生的稳定退款号建立一张 `source=system_duplicate_core`、`status=requested` 的售后单，写审计并通知付款人。**已创建售后单不代表钱已退回。**
5. 重放相同事件直接返回；新事件号重报同一成功交易也不重复建权益、售后或提醒。并发结算由 SQLite 事务串行保证同一家庭只有一笔新授予。

原买断完成退款、相关权益已经撤销后，再确认另一笔新收款可以正常获得一份新买断权益。已经标记为重复并进入售后的订单不会因为原买断后来退款而被悄悄转换为正常履约。

## 用户端

网页/App 在“家庭与偏好设置 → 产品与 AI 权益”查看本人订单和售后状态。小程序在家庭空间的产品区域查看订单并刷新状态。

- `requested`：待售后核验，尚未退款。
- `processing`：渠道处理中，或网络结果不确定，不能显示已退。
- `succeeded`：服务端已核验渠道退款成功。

普通家人、家庭统筹均不能读取他人订单与售后详情；系统售后管理员通过单独的管理接口处理。订单刷新读取已保存售后状态，不代替管理员对渠道结果的查询。

## 管理员处理

设置服务端 `ADMIN_USER_ID` 后，在“家庭与偏好设置 → 售后退款管理”查看售后单。

1. 核对退款原因、订单、收款渠道和金额。
2. 进入核对页，再选择“确认提交原路退款”；该最终操作会调用真实渠道，必须具备正确商户配置和操作权限。
3. 网络结果不确定时，先查询渠道退款结果。必要时重试同一退款号，不能另建一单。
4. 只有符合原订单、交易、退款编号和金额的成功响应才完成退款。只撤销这笔订单来源的权益；重复订单本来没有新权益，原买断和赠月保持不变。

此版本不会在支付回调、页面加载或浏览器自动检查中自动提交退款。一般支付回调处理与实际退款资金操作保持分离。

## 验收与限制

已使用临时数据库和模拟支付响应验证顺序/并发收款、跨渠道、晚到回调、重复事件、退款超时、退款后回调重放、权益来源隔离、普通续费与不同家庭隔离。页面检查使用虚构账户和交易，没有发起真实扣款或退款。

未实现每日渠道账单下载与自动对账、历史重复权益批量修复或无人值守退款。现有历史数据不做自动资金或权益迁移；如有已存在的重复收款，需售后核验具体记录。真实商户、证书轮换和小程序/App 真机联调仍须另行验收。
