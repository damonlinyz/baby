# 日历导出

网页与 HTML5+ 共用页面可在“行动清单 → 导出日历（ICS）”下载文件；小程序在相同入口通过微信文件导出界面保存或转交。导出前确认保存说明，选择起止日期，最多 366 个日历日，截止日包含在内；默认按家庭时区从今天到 90 天后。

## 范围与隐私

- 每次由服务端重新校验当前成员与授权，只包含调用人当前可见的任务和预约；不使用打开页面时缓存的数据拼接日历。普通成员仅导出自己的任务；健康与宝宝事项分别遵守各自授权。
- 仅导出有日期的待完成、进行中、待确认任务及待进行预约；未定日期、已完成、跳过、取消事项不导出，物品不进入日历。
- 文件包含事项标题、全天日期、稳定的匿名事件标识与修订号，不含备注、成员姓名、原始账号/事项 ID、邀请信息及自动提醒。标题与日期仍可能涉及健康资料，因此导出界面要求单独确认。
- 文件里的 `CLASS:PRIVATE` 仅是日历属性，不能替代目标日历的访问控制。导入或分享后的副本由使用者自行管理；改期、完成、删除或撤回授权都无法追回既有副本。这是一次性导出，未提供公开订阅地址或自动同步。
- 不超过 2,000 个事项；超过时整批拒绝并要求缩小范围，不静默截断。

## 日期与重复任务

使用 RFC 5545 `VEVENT`，`DTSTART;VALUE=DATE` 为安排日期，`DTEND;VALUE=DATE` 为次日（排他的结束日）。不把家庭日历日期换成设备时区的午夜时间戳，跨时区导入仍是同一天。没有自行编造预约时刻、提醒、参与人或医疗安排。

重复家务仅导出已生成且可见的独立实例；当前系统提前生成至家庭今天后第 14 天。文件不会用 `RRULE` 推算未来实例，以保留单次改期、跳过和停止后的实际安排。需要更远日期时，待后续实例生成后再次核对导出。

同一家庭、记录、类型产生稳定匿名 UID，版本作为 SEQUENCE；导入软件如何处理重复导入由其自身决定，不能保证每种日历都自动替换旧事件。标题按 iCalendar 文本规则转义换行、逗号、分号和反斜杠，删除控制字符；每条物理行最多 75 个 UTF-8 字节，使用 CRLF 和续行，不拆开中文字符。

## 接口和本地文件

`GET /api/calendar?family_id=...&start=YYYY-MM-DD&end=YYYY-MM-DD`

接口需要当前会话，返回 JSON `{filename, content, event_count, start, end}`，沿用网页和小程序的会话失效处理；浏览器将 `content` 保存为 `text/calendar;charset=utf-8` 文件。响应禁止缓存。审计仅保存日期范围和数量，不存导出原文。

小程序需要支持 `shareFileMessage` 的微信版本。临时文件写入应用私有目录，导出成功、取消或失败后删除；异步写入后复查账号、家庭与服务地址，已切换时不打开文件交付界面。进程中断可能遗留本次已确认导出的临时文件；下次启动按专用文件名清理，不删除其他文件。外部保存的副本无法自动删除。当前已完成适配器模拟，真机文件导入和微信版本兼容性仍待验收；网页端可作为替代入口。
