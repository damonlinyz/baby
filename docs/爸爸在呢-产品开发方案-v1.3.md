## 1. 产品概述

### 1.1 一句话定位【保留并明确】

「爸爸在呢」是一款以爸爸为统筹核心的全家协作式孕产育儿助手小程序：从怀孕到产后再到宝宝 1 岁，用时间轴组织该懂的知识、该办的事项、该准备的物品，由确定性规则保障基础安排，AI 补充个性化解释与简报。

- **爸爸 = 表率 + 统筹：**学习、规划、分工、跟进，不获得替他人授权健康信息或替代医疗决定的权力。
- **妈妈 = 有自主权的参与者：**能看到家庭准备、表达需求、按配置确认家庭事务；本人敏感健康信息的采集、共享、AI 使用由本人控制。
- **其他家人 = 科学学习者 + 执行者：**接收策展知识与明确分工，完成自己的任务；不修改全家规则与临床日期。

### 1.2 产品机会与边界【变更】

保留原判断作为产品假设：爸爸的痛点是“想帮忙但不知道何时、如何做”，家庭需要共同进度与可信知识。原方案列举的美柚、宝宝树、丁香妈妈、亲宝宝仅为竞品观察线索，不视为已核实的当前市场结论。

**当前目标是开发者本人和真实家庭长期用得顺手。**不安排市场验证，不因访谈、种子用户规模、留存或付费转化率推迟开发。自用验收关注少遗漏、少重复操作、协作清楚、数据可靠。

产品边界：不做电商或导购佣金、不做泛社区、不做在线诊断与处方、不做广告变现。收入限于核心产品买断及独立 AI 服务收费。UGC 不纳入当前路线，原“二期经验贴/社区”降为远期候选，需另行定义边界与审核能力。

### 1.3 核心价值主张【保留】

| 角色 | 价值 |
|---|---|
| 爸爸 | 本周要做什么、谁负责、哪些待确认一目了然；形成统筹习惯 |
| 妈妈 | 看见全家准备，同时保有个人数据与选择的控制权 |
| 家人 | 接触经过审校的科学内容，有清晰可执行的任务 |
| 家庭 | 少遗漏、减少反复沟通，用同一套可溯源知识讨论 |

## 3. 用户与场景

### 3.1 用户画像【保留】

初始设计面向 25—40 岁准爸爸，一胎、碎片时间、想帮忙又怕做错。通勤看知识、产检前核对材料、晚间整理任务是主要场景。支持爸爸独自先用；妈妈未加入时仅建家庭事务与必要时间安排，不由爸爸代勾妈妈的健康授权。

### 3.2 生命周期【变更】

备孕暂不做 → 孕期 → 分娩后妈妈产后恢复与宝宝成长并行 → 宝宝满 1 周岁后归档浏览或新孕次。

**删除固定“约 14 个月服务周期”。**从孕早期开始到宝宝 1 岁通常跨越更长时间，随加入时间而变；生命周期不作为买断到期时间。一个家庭可保存多个孕次，第一期默认同时管理一个活跃孕次；多胎支持多个宝宝资料，不输出普通单胎的个体医疗排程。满周岁按日历周年计算，不用固定 365 天。

### 3.3 五大核心场景【保留并修订】

1. 每周规划：基础规则生成本周任务；有 AI 权益时增加“三件重点事”的个性化解释。
2. 每日执行：爸爸与家人完成分配任务；需确认的完成项进入待妈妈确认。
3. 临事查问：如“糖耐检查前要准备什么”，按预约机构要求与已审校知识解释。
4. 采购协同：待产包共同执行，爸爸统筹，分享默认仅发布去隐私模板预览。
5. 被看见：妈妈查看家庭动态、点赞与反馈；避免“监工”和羞辱式文案。

### 3.4 特殊场景【新增】

支持日期未知、预产期修订、提前分娩、超过预产期未分娩、妊娠结束、失去宝宝、暂停使用、成员退出与二胎。任何不良结局均不自动推断；由用户主动记录，立即停止庆祝、排行榜与相关催促推送，提供安静模式和资料归档。

## 4. 功能详设（MVP 一期）

### 4.1 孕周时间轴与状态机【变更】

#### 4.1.1 日期口径

- 用户可录入 LMP 或 EDD。仅用 LMP 时以 `LMP + 280 个日历日` 产生**估算** EDD；不假设月经规律，不以此覆盖医生确认日期。
- 当前有效 EDD 有来源：`lmp_estimate / clinician_entered / user_entered`。医生确认日期由用户转录并标明来源，产品不宣称已经核验病历。
- 定义 `calendarDiff(a,b)` 为家庭时区下日期 a 减日期 b 的日历天数；`孕龄天数 = calendarDiff(today, effective_edd − 280天)`，显示 `floor(孕龄天数/7)w + (孕龄天数%7)d`，先校验孕龄非负再格式化。
- 全部日期计算使用家庭 IANA 时区，默认 Asia/Shanghai；日期为 `YYYY-MM-DD`，事件时间 UTC 存储。跨时区旅行不自动改家庭时区。
- 0w+0d 有效；负孕龄或明显矛盾输入阻止提交并请核对。超出模板覆盖窗口仍显示真实孕龄，不锁死 40 周、不自动视为已出生。
- 阶段采用本产品的内容分组：孕早期 `<14w`、孕中期 `14w—27w+6d`、孕晚期 `≥28w`；这是产品路由口径，模板另按审校来源设置有效窗口，不替代诊疗标准。
- 日期未知可进入 `dating_pending`，仅展示不依赖孕周的基础准备；不推测孕周，不生成精确产检节点。

#### 4.1.2 状态分层

生命周期状态、孕期内容阶段、服务暂停、数据归档分开存储，避免一个 `stage` 承担全部含义。

| 当前状态 | 事件与前置 | 新状态 | 副作用 |
|---|---|---|---|
| dating_pending | 提交有效日期 | pregnant | 生成任务实例与基础时间线 |
| pregnant | 修订 EDD；记录来源与原因 | pregnant，版本+1 | 预览差异，重排尚未完成的系统任务与通知 |
| pregnant | 到达 EDD | pregnant | 显示“已到预产期，请以医生安排为准”；不自动分娩 |
| pregnant | 用户确认分娩日期、结果 | postpartum | 终止孕期待办，生成产后任务与宝宝档案 |
| pregnant | 用户确认妊娠结束，记录必要日期 | pregnancy_ended | 撤销孕期/宝宝促活通知，转可选支持内容 |
| postpartum | 产后第 43 个日历日 | postpartum | 妈妈恢复视图转常规支持；宝宝按日龄继续成长 |
| 任意非删除状态 | 主动暂停 | 原状态保留，paused=true | 停止普通通知和自动简报 |
| 暂停 | 主动恢复 | paused=false | 重算当前任务，不补发积压通知 |
| postpartum/pregnancy_ended | 用户归档 | archived=true | 只读历史；新孕次建立新 ID |

分娩当天为产后第 0 天，0—42 天使用原“月子期”内容标签；第 43 天起转后续内容。宝宝年龄独立计算。妈妈产后状态不因宝宝归档、早产或失去宝宝被删除。妊娠结束的原因可不填，不能为流程强制收集。

#### 4.1.3 早产、多胎和不良结局

每名宝宝记录出生日期、出生孕龄（可未知）、成长状态；纠正年龄仅在信息完整且经审校内容适用时显示为辅助标签，不自动改写实际月龄或疫苗、检查时间。NICU、早产与多胎场景以用户录入的医嘱安排为准，不套普通模板做个体建议。

多胎的每个宝宝可有独立结果；部分宝宝失去时关闭相应庆祝内容，不能把整个孕次简单标为普通成功分娩。第一期保留资料与人工安排能力，不生成复杂临床计划。

#### 4.1.4 状态修改事务与验收

每次事件有 `event_id、actor、before/after、reason、effective_date、version`。爸爸可发起家庭时间线变更；涉及妈妈健康日期的变更由妈妈提交或在其有效授权范围内由爸爸代录；家庭二次确认关闭也不能越权。

提交前展示影响数：“将调整 X 条待办、取消 Y 条提醒”。已完成任务保留当时孕龄与模板快照，不移动历史；用户手改预约默认不被重排，冲突列为待核对。重放同一事件不得重复建档、任务或发通知。纠错采用补偿事件，保留原审计；已出生宝宝档案不能靠直接改状态抹除。

必测：0w、13w+6d/14w、27w+6d/28w、40w+后、产后 42/43 天、闰年周岁、跨午夜、EDD 前后移动、重复分娩事件、撤销误录、流产后停推、暂停恢复、多胎不同结果。

### 4.2 准爸爸任务系统【保留并生产化】

保留 80—120 条模板的正式内容目标；首个自用闭环先做 20—30 条，按阶段补齐，不用未审校生成文本凑数量。任务结构：标题、为什么重要、步骤、关联知识、“问 AI”、适用窗口、负责人、截止日期、完成与确认状态。

| 原任务示例 | v1.3 可执行口径 |
|---|---|
| 6—8 周陪同 B 超确认胎心 | 保留陪同与准备事项；检查时间以医生预约为准，不承诺固定周数必有结果 |
| 11—13 周 NT、建档 | 保留材料准备；具体检查窗口由有来源的当地模板配置 |
| 16—18 周唐筛/无创 DNA | 改为“了解筛查选择、按医生安排预约”；不由 AI 替家庭选择项目 |
| 24 周糖耐、前一晚空腹 | 改为按机构预约提醒，准备要求引用机构/审校内容，不写成统一禁食指令 |
| 28—32 周待产包 | 保留，与清单关联 |
| 36 周医院路线、待产准备 | 保留，相关异常情况卡由专业审校，不用模型现写应急步骤 |
| 产后出生证明、户籍、医保 | 保留，注明城市、政策版本、核验日期 |
| 拍嗝、尿布、冲奶等 | 保留图解/短视频，适用条件与版权来源齐备 |

删除原“陪数胎动 15 分钟”的固定通用任务，改为“了解医护建议的观察方式”；不使用打卡次数暗示医疗达标。

任务状态：`todo → in_progress → submitted → done`；无需确认时 `submitted` 可直接到 `done`；可 `skipped/cancelled`，记录原因。妈妈拒绝时回到 `in_progress` 并保留意见。执行者只能提交分配给自己的任务；爸爸可调整分工，不伪造他人完成。到期是时间属性，不用“逾期”作为互斥状态。

自定义任务、改期、跳过、恢复、重复任务、撤销完成均需支持；重复任务按周期生成独立实例。医疗类任务不因过期自动补做，展示“请核对后续安排”。打卡一键完成保留暖色动效；文案改为“又准备好一件事”，不使用内疚或恐吓式催促。

### 4.3 待产包清单【保留并明确协作】

三套清单：妈妈入院包约 25 项、宝宝用品约 35 项、证件资料约 10 项。每项保留名称、分类、参考价格区间、必备/建议/可选、备注；增加数量、负责人、准备状态、来源版本、价格更新时间。

支持勾选、增删改、紧急度、进度环；爸爸维护结构并分配，家人更新自己负责项。采购完成按家庭策略决定是否待确认。自定义内容不被模板升级覆盖。清单项 AI 入口保留“如何判断是否需要、预算怎么安排”，不导购、不承诺品牌医疗功效。

分享海报保留小程序码：默认只含通用模板与总体进度；姓名、日期、诊疗、家庭动态和实际物品备注默认不出图。扫码落地只到公开模板预览，加入家庭仍须邀请及确认。私密分享用限时可撤销令牌，不能用可枚举 family_id 访问。

### 4.4 AI 问答与主动简报【变更】

中央入口、任务/清单内嵌提问、阶段标签保留。上下文只含提问者获授权的数据；“家庭有妈妈成员”不等于可以读取妈妈健康资料。首期只向爸爸开放自由问答，妈妈问答留二期；其他家人只学习与执行。

删除免费每日 5 次与会员无限。免费为静态示例/知识检索，不持续赠送模型调用；买断赠送 30 天有限额 AI，后续独立购买，配额见 10 章。AI 到期仍可用完整基础任务、提醒、知识来源、清单与历史数据。

每周一家庭时区 08:00 展示简报。静态“三件事”对核心用户完整可见，不打码安全相关信息；AI 权益有效且允许个性化时生成增强解释。过期则回退静态卡，历史简报仍可读。简报不得新增未经确认的医疗安排，不将执行情况评价为“胎儿一定健康”。

### 4.5 提醒系统【变更】

保留产检前 3 天、前 1 天及任务截止提醒为可配置默认值；已预约日期优先于通用窗口。计划模板注明地区与内容版本，可录入医院名称/材料要求；具体敏感信息仅本人授权可见。

通知类型分为预约、任务、确认请求、周报；按用户偏好设置静默时段、合并上限、渠道开关。一次性订阅资格逐次记录，不能把一次同意视作永久可推送。

**删除“未订阅就用服务通知兜底”的保证。**仅在平台支持、已获对应许可的渠道发送；无资格、失败或拒绝时回到站内待办/红点与可选日历导出。订阅消息不是医疗预警或可靠急救通道。外部通知只写“你有待查看事项”，不展示病情、检查结果或妊娠结束原因。

通知状态 `scheduled/claimed/sent/failed/cancelled/expired`；保存发送去重键、重试次数、平台回执。每次发送前重查日期版本、成员权限、暂停与授权，失效立即取消。发送超时状态不明先核对回执，避免盲目重复。

### 4.6 家庭共享、角色与确认【变更】

#### 4.6.1 家庭成员与默认视图

爸爸创建家庭 → 生成限时邀请 → 对方登录看清将加入的角色与可见范围 → 确认加入。邀请不能授予敏感数据权限。邀请码单次或有限次数、有到期时间、可撤销，服务端限流；新成员默认最小权限。

- 爸爸：全家任务与清单统筹、成员管理、知识与 AI 入口。
- 妈妈：简化首页，家庭准备动态、待确认事项、点赞、自己的健康授权管理。
- 其他家人：大字知识卡、自己的执行任务；默认不看健康日期、全家私密动态或 AI 对话。
- 独自使用也能工作；妈妈未加入时确认策略为 `off`，系统明确显示“尚未启用妈妈确认”，不得伪造已确认。

#### 4.6.2 权限矩阵

| 能力 | 爸爸 | 妈妈 | 其他成员 |
|---|---|---|---|
| 家庭普通任务创建/分配、清单结构修改 | 统筹 | 提需求；可按授权协作 | 否 |
| 完成自己分配的任务/清单项 | 是 | 是 | 是 |
| 查看家庭准备进度、点赞 | 是 | 是 | 仅授权的非敏感摘要 |
| 查看策展知识 | 全量适用内容 | 自身护理内容 | 定向推送、封闭策展 |
| 发起家庭规则和时间线变更 | 是；健康资料另鉴权 | 本人健康日期可提交 | 否 |
| 审批指定家庭变更 | 不替妈妈确认 | 是 | 否 |
| 本人健康数据采集/共享/用于 AI | 仅本人或持有效本人授权 | 本人决定 | 仅本人决定 |
| 他人 AI 私聊 | 默认无权 | 默认无权 | 无权 |
| 成员移除与统筹转交 | 是；不能移转个人授权 | 可退出、撤回授权 | 可退出 |

“爸爸最终统筹”适用于普通家庭安排；医疗选择、身体自主与隐私授权无家庭管理员最终覆盖权。

#### 4.6.3 妈妈二次确认策略

`off`：普通家庭事务由爸爸安排直接生效；`selected`：仅选定类别需要妈妈确认；`all_key_changes`：所有关键家庭变更需要确认。默认 `off`，在家庭设置清楚展示；妈妈加入后可共同启用，不能默认让她承担所有审批。

可配置范围：孕期时间线共享变更、重要预约改期、关键任务完成、采购预算阈值/大额项、邀请新增成员。小额日常执行默认无需二次确认。涉及本人健康信息仍需其单独授权，与模式无关。

审批记录绑定 `resource_id + proposed_version + payload_hash`；状态 `pending/approved/rejected/expired/cancelled`。待确认不生效；到期不自动同意，默认 48 小时可配置，可取消重提。修改待审批内容使旧审批失效。设置从需要确认改成无需确认也属于关键变更：当前已启用策略下需妈妈确认，防止爸爸临时关掉绕过；待审批使用提交时策略并检查后续权限，策略更严格时重新确认。

成员退出、失联或紧急事项可取消审批、暂停任务并提示线下沟通，不因没有确认阻断就医。爸爸可提出重置家庭普通协作模式，但不能借重置取得他人健康资料；妈妈退出时其授权即时失效，共享视图收缩为普通事务。

#### 4.6.4 家庭权益与后续

免费演示最多 2 人；核心买断家庭最多 5 人（含爸爸妈妈）。一个家庭一个活动统筹者，同账号可加入不同家庭但权限按家庭关系计算，不在 users 写死角色。转交统筹需接收人确认、旧统筹失权，支付归属不随之转移。

一期支持分配任务与家人提交完成，妈妈更丰富的编辑、宝宝记录、学习任务编排留二期。长辈课堂与温和辟谣专栏保留后续：捂月子、挤乳头、把尿、嚼饭喂娃、剃胎毛等均需逐条审校，不把“传统”整体污名化。

### 4.7 游戏化【调整】

保留连续打卡、成就徽章（首次陪产检、待产包准备、出生里程碑、连续 30 天）、每周爸爸报告。断签允许自然中断，不说“老婆昨天可辛苦啦”。早产、丧失、住院、暂停时可关闭火焰与庆祝；报告以完成事实为主，不评价父母是否合格。

亲友小队榜保留为一期之后增强项：2—5 位爸爸自愿加入，仅共享授权后的周完成比例，不展示孕周、诊疗、妻子资料。全国匿名同期榜远期，需足够聚合样本与再识别评估；绝不模拟排名或百分位，数据不足显示“数据积累中”。

### 4.8 知识库【保留并加版本】

阶段 × 主题 × 目标角色：产检、营养、分娩、产后护理、新生儿护理、心理支持、法律手续。首页 3—5 张知识卡，按角色和适用性过滤。

爸爸可查已审校全量适用内容；妈妈先做自身护理阅读；长辈封闭策展、不接 UGC、不提供开放网络检索与自由搜索。不能阻止用户系统截图或外部上网，产品只约束自身入口与数据访问。

保留权威指南结构化、AI 草拟后审校、人工网络资料研究三类生产方式；网络研究结果不直接进入用户回答。每条正式知识具备来源、适用地区/人群、审校人、有效时间、版本、引用许可。来源溯源属安全基础能力，不收费隐藏。

### 4.9 本期范围汇总【变更】

| 自用核心先做 | 公开一期补齐 | 后续候选/不做 |
|---|---|---|
| 时间轴、状态事件、任务、自定义改期 | 妈妈确认策略、邀请与家人执行完整流程 | 宫缩/胎动工具、妈妈 AI、丰富宝宝记录后续 |
| 三套清单、基础知识、站内提醒 | 订阅消息、隐私分享图、权限审计 | 学习任务编排、长辈课堂、小队榜后续 |
| 本人真实家庭的最小协作 | 买断/AI 支付、退款、配额、合规材料 | 全国榜、App 后续 |
| 安全限定的 AI 问答、自用简报 | 全链路安全评测、内容覆盖、备份恢复 | UGC/模板市场需另立项 |
| 简单打卡和爸爸报告 | 徽章、提醒设置与运维后台 | 电商、泛社区、诊断处方、广告不做 |

## 5. 交互与视觉设计

### 5.1 信息架构【保留】

3 区导航：首页 / 中央凸起 AI 按钮 / 我的。首页直接打卡、看清单；任务与清单内保留场景化问 AI。“我的”包括家庭、购买与 AI 用量、提醒、隐私授权、数据导出与删除；排行榜入口仅在对应阶段开放。

### 5.2 首页结构【保留并变更】

1. 时间轴进度、当前阶段、距 EDD 天数或宝宝年龄；水果类比为情感插画，不标示个体发育结论。日期未知、产后、不良结局有独立空态。
2. 本周三件事：基础完整显示，AI 有权益时增强解释。
3. 今日任务和待确认事项；任务可直接提交完成。
4. 本周知识卡横滑，来源一键展开。
5. 待产包进度与最近缺的 3 件。

妈妈首页优先家庭准备和确认，其他家人首页优先学习与自己任务。暂停/妊娠结束时替换庆祝和催促，不留孕周营销卡。

### 5.3 核心流程【变更】

- 新手：说明产品 → 必要登录 → 创建/加入家庭 → 可跳过日期 → 提供来源信息 → 显示估算或确认日期 → 第一件非医疗任务 → 在实际需要时申请通知。头像昵称不强制获取。
- 妈妈加入：接受邀请 → 看权限 → 独立选择健康数据处理、家庭可见、AI 处理，拒绝仍可参与普通任务。
- 完成任务：点击 → 若需确认显示待确认，否则完成 → 可撤销；离线显示待同步，不假装云端已保存。
- 时间线变更：填写 → 看影响 → 如需审批则待确认 → 服务端事务生效 → 通知/待办重排。
- 分享：预览脱敏海报 → 保存/分享 → 对方查看模板；私密内容另走授权。
- 购买：展示买断与 AI 的分离权益、期限与额度 → 支付 → 服务端核验 → 展示到账结果；异常提供恢复购买/客服查询。

### 5.4 视觉规范【保留】

暖橙 `#F2935C`、米白 `#FDF8F2`、深棕 `#3D2C29`；柔和投影与手绘插画。圆角用统一设计 token，小程序 rpx 与 App dp 单独映射，保留原 12—16rpx 风格参考但须实机检查。文字对比度、长辈大字、按钮触达区、读屏标签和低性能设备动效降级纳入验收。

文案有共情、不说教、不羞辱、不制造焦虑。AI 页面常驻“AI 生成”标识与局限说明；急症路径使用清楚直接的提示，不套温情玩笑。

## 6. 技术架构

### 6.1 总体架构【保留并增强】

```text
微信小程序（Taro / React / TypeScript）
  → 统一 API：身份认证 → 家庭/资源/字段/用途授权 → 参数校验
  → 领域云函数：family / pregnancy / task / checklist / approval
                  knowledge / ai / briefing / notify / payment / entitlement
  → CloudBase 数据库与私有云存储
  → 事务 Outbox → 异步任务执行器 → 通知、简报、索引、数据删除
  → 外部模型网关 / 检索服务 / 微信支付与消息接口
管理端 → 运营与审校权限 → 版本发布、支付核对、告警与审计
```

用户端不直接写业务集合；必要的直读也受安全规则限制，敏感对象优先服务端投影返回。模型密钥、支付证书放密钥管理，前端与代码仓库不包含。

### 6.2 前端【保留】

Taro 4.x 作为预研候选版本线，开工时锁定经实机验证的具体版本；React、TypeScript、Zustand、NutUI-React-Taro 打底并自研主题。重点组件：时间轴环、任务卡、清单折叠面板、AI 对话、canvas 海报、确认面板。

共享领域规则与 API 类型，平台登录、支付、推送、文件、富文本、样式适配单独封装。RN/App 需验证组件和原生桥，不能把“跨端”当作无需额外开发。

### 6.3 后端与异步处理【变更】

云函数按域拆分，金额、权益、状态更新在服务端进行。定时器只负责扫描并入队，不能遍历全部家庭串行调用模型。家庭时区每周一 08:00 发布；可提前生成，发送前复核授权、状态、权益。每天 09:00/20:00 的原扫描设想保留为批处理触发点，实际预约提醒按 `next_run_at` 调度，避免固定扫描漏窗口。

核心状态修改和 Outbox 在同事务提交；执行器幂等处理、指数退避、死信告警；任务失败可重放。数据库若不支持所需复合唯一约束，采用确定性文档 ID + 事务校验，不以“先查后写”冒充唯一性。

API 写操作统一带 `request_id、expected_version`；409 冲突返回最新版本，避免两人同时勾选覆盖。日志只记 trace_id、对象 ID 与脱敏摘要，不默认记录健康原文和完整对话。

### 6.4 部署、运维与迁移【新增/变更】

开发/测试/生产环境隔离，测试只用合成或脱敏数据。数据库 schema_version 与可重跑迁移脚本受版本控制；发布采用功能开关，可独立关闭 AI、生成简报、邀请、支付入口。

监控 API 成功率、队列积压、AI 费用、通知失败、支付权益差异、越权拒绝异常。目标为基础 API 月可用性 99.5%，不作为未经验证的对外承诺；AI 故障不拖垮任务与清单。

初始恢复目标 RPO≤24 小时、RTO≤8 小时；每日加密备份、至少月度恢复演练，结果留档。删除请求同步写删除标记；恢复备份后先重放删除与撤权再对外服务。第一期实现简明管理端：知识审校、用户问题、订单对账、队列重试、审计查询。

不以用户过 1 万自动迁移：根据云函数时长、并发、成本、数据库检索能力决定容器化。领域服务与存储适配隔离；迁移需校验数量、权限、权益账本与回滚，不能假设云函数直接平移即可。

## 7. 数据结构设计（云数据库集合）【整体变更】

### 7.1 建模约定

ID 为不可猜随机值；成员角色在关系表；同一账号可有多个家庭关系。公共审计字段：`_id、schema_version、version、created_at、updated_at、created_by`；适用对象另有 `deleted_at、family_id、pregnancy_id、owner_id、visibility`。时间戳 UTC，业务日期与时区独立，金额整数分、币种 CNY。

敏感字段独立集合或字段级加密，普通任务中不复制病历。查询先按已鉴权 family_id/owner_id 收敛，返回字段由服务端按权限投影；不信任客户端传入 user_id/role。下表是最小生产字段集，开发时转换为版本化 schema 与枚举校验。

未绑定 subject_user_id 不等于已经匿名；如日期、备注等仍可关联到具体妈妈，仍按其敏感信息处理。妈妈未注册时可通过独立授权页面完成本人告知与同意，证据可后续绑定账号；未取得时只用虚构日期演示或不关联具体个人的通用计划，不上传真实健康资料。

## 8. AI 与 RAG 知识库架构

### 8.1 安全问答链路【整体变更】

```text
登录/权限/用途授权检查 → 最少上下文 + 输入脱敏
 → 确定性规则与语义模型联合风险识别
 → R3 紧急风险：审校静态提示，停止生成
 → R2 个体医疗判断：边界说明 + 联系专业人员 + 可核验通用知识
 → R1/R0：适用性过滤 → 检索有效知识 → 证据不足则停止个性化回答
 → 受约束模型生成结构化答案 → 引文/主张/越界/隐私校验
 → 校验失败回退静态知识或明确无法回答
 → 显示 AI 标识、有效引用、适用范围 → 审计、配额结算
```

| 风险级别 | 例子（非完整医学清单） | 路径 |
|---|---|---|
| R0 普通事务 | 待产包分类、证件材料整理 | 正常问答，区分地区与政策时间 |
| R1 健康教育 | 检查目的、常见术语、通用护理知识 | 仅基于审校证据，说明适用条件 |
| R2 个体医疗 | 根据化验单判断风险、要不要用药、是否停药 | 不诊断、不推荐个人剂量、不代做决定；提供就诊沟通问题 |
| R3 可能紧急 | 孕产严重异常、新生儿急性异常、自伤风险等 | 固定安全路径，建议尽快联系当地急救/医院；不先问完信息才提示 |

风险判定使用当前提问与必要历史，识别否定、转述、错别字、方言、模糊症状与上下文变化；不能只有关键词。风险未定时保守升级，不输出“没事”“观察到明天”类安抚判断。紧急静态提示不受付费配额限制，模型/分类器超时也有静态故障提示。产品不承诺急症识别完备或替代医疗服务。

#### 8.1.1 生成与证据约束

- 检索先按地区、人群、孕龄、角色、版本、有效期筛选，Top 5 只是初始参数，须由评测调整。
- 提供结构化输出 `answer、claims、citation_ids、risk、limits、follow_up`。引用 ID 必须来自本次检索，主张必须有对应证据；来源冲突明确说明，不能模型自行调和出个体医嘱。
- 不能回答时展示相关原文摘要与来源或明确证据不足；免责声明只是告知，不替代拦截。
- 健康回答先完成检查再整段展示，防止危险片段先流出；普通事务如做流式也要限制未审片段。模型输出中的 HTML、外链、指令均过滤或白名单处理。
- 用户、文档与检索内容都按不可信数据处理，隔离系统指令；禁止根据文档内指令读取别家资料、泄露提示词或调用写操作。
- AI 只能提出任务草稿，用户明确提交后经普通权限/审批 API 生效；不得操作支付、改 EDD 或自动邀请家人。
- 一期不做病历照片、检查报告 OCR 和图像诊断；后续须另设授权、去标识与专项评测。

### 8.2 每周简报【变更】

基础任务与知识由规则引擎先选，AI 只改写与排序解释。队列按家庭/授权收件范围分页、限并发；同一 `family + pregnancy + week + context_revision + audience` 幂等。个人敏感信息不生成全家公共简报；共享版只含允许公开的事务。

日期变更、分娩、妊娠结束、撤权触发失效，重新生成前展示静态卡。AI 失败、无配额、无授权均用已审校静态“三件事”；失败不扣用户可用额度。简报不产生未经用户确认的新产检预约。

### 8.3 成本与配额【变更】

删除 v1.2“全生命周期 AI 成本 ¥3—8”的未经实测结论。按实际请求计费记录输入/输出 token、检索、重试、分类、embedding、简报成本，价格从已选供应商报价配置导入，不硬编码在商业承诺里。

一期套餐采用按次预算：30 天内最多 300 次成功问答、5 份 AI 周简报；输入总上下文每次最多 8,000 token、输出最多 1,000 token（均为技术上限，前端提前显示超限处理）。不提供“更强模型无限用”。同家庭最多同时 2 个生成请求，每个付费周期共用 AI 额度，只有有权限的成员可调用。

配额流程：请求去重 → 原子预占 → 调用 → 成功校验后结算；失败释放。供应商已产生但用户未收到的费用进入平台成本，不转扣成功次数。超时重试沿用 request_id；结算器回收过期预占。

缓存仅用于公开通用问题，键包含规范问题、适用人群、地区、知识/安全/提示词/模型版本；不跨家庭缓存敏感个性化答案。原“缓存命中率 >40%”降为观测项，不能作为成本成立前提。可控制上下文截断、并发、每日预算和全局熔断；用尽 AI 后静态服务继续。

### 8.4 内容管线【保留并增强】

首个自用阶段 50—100 条精选内容，公开一期目标 300—500 条，但以覆盖与审校为发布标准。来源优先国家/地区卫生主管部门、专业组织指南和有许可书籍；国际资料注明地区差异，不能直接作为国内产检排程。

状态：`draft → in_review → approved → published → retired`；医疗内容须具备相应专业能力的审校者确认，开发者自用反馈不能替代医学审校。审校人、来源日期、适用人群、复核到期时间必填。高风险内容至少季度检查是否需复核，来源更新或投诉触发即时复核；到期未复核则暂停个性化引用。

AI 草稿与人工网络研究只进入草稿区；不得抓取未授权版权内容批量上线。发布形成不可变知识 release，向量索引与原文一起切换；更新留版本映射与回滚能力。反馈内容默认脱敏汇总，不用完整健康对话做训练。

### 8.5 评测、故障与安全事件【新增】

公开一期维护至少 300 条分层回归题，包含至少 100 条高风险及对抗表达；覆盖孕期、产后、新生儿、多胎/早产、药物、来源冲突、证据缺失、提示注入、跨家庭与授权撤回。

发布门槛：固定评测集里 R3 关键漏拦截、个体诊断/剂量输出、伪造引用、越权泄漏均为 0；任何一例阻断发布并新增回归题。此门槛只是测试集验收，不能宣称现实世界准确率 100%。另记录误拒答率、证据支持率与可读性，由审校者抽检。

模型、提示词、知识 release、风险策略、embedding 任一变化需跑相应回归并灰度；异常回滚到上个安全版本。P0：可能严重伤害的回答或隐私泄漏，立即关闭相关生成路径、保留最小审计、撤缓存、评估影响并修复后再开。P1：普通错误/引用失效，停用对应内容，静态降级。设置反馈入口与处理责任人；独立开发者本人负责值守，做不到时保持 AI 关闭或受限，不伪称 24 小时人工医疗响应。

- 后续 AI 只手动续购；到期不自动扣款。提前续购按现有周期结束顺延，配额每周期独立、不提前叠加无限用、不结转；UI 展示每期起止与剩余。
- 现阶段仅爸爸可调用自由问答，额度归绑定家庭的 AI 权益，共享家庭席位不代表人人都有对话权限。到期保留历史问答和简报，读取仍受权限及保存期限约束。
- AI 暂停、用完、过期不锁核心数据、不关闭基础提醒、不遮挡风险提示和知识来源。免费静态安全提示始终可达。

### 10.3 成本预算与价格门槛【新增】

`每周期贡献 = 实收 − 支付费用 − 问答成本 − 简报成本 − 安全/检索成本 − 分摊云资源与售后退款成本`。

以下仅为敏感性计算，**不是供应商实时报价**：假设 AI 包实收 ¥25、支付费用按 1% 预算（¥0.25）、5 份简报每份 ¥0.10（¥0.50）、其他可变成本暂估 ¥2，则：

| 每次成功问答含安全检查的平均成本 | 300 次成本 | 周期剩余贡献（未含固定人力） |
|---|---|---|
| ¥0.01 | ¥3 | ¥19.25 |
| ¥0.03 | ¥9 | ¥13.25 |
| ¥0.08 | ¥24 | -¥1.75 |

试算说明 300 次上限不能替代实测。公开收费前至少用 200 次代表性调用记录均值、P95、最长上下文、失败重试和满额场景成本；拟定满额可变成本预算≤¥12.5，超出则在开售前调整模型/配额/价格并更新商品页。已售周期不得中途缩水。

买断贡献另算：`128 − 手续费 − 赠月AI实耗 − 长期核心服务准备金 − 售后/退款分摊`。数据库、存储、备份有长期成本，按活跃家庭月成本与多年度使用情景估算准备金；不能用一次性买断收入全额当利润。触发平台费用预算告警时可限售新 AI 包，不得扣减已售核心权益。

### 10.4 支付与退款可执行流程【新增】

订单 `created → pending → paid → closed`，退款为 `refund_pending/partially_refunded/refunded` 独立状态投影。服务端生成价格和订单号，不接受前端金额；客户端“支付成功”仅用于展示等待，不能授予权益。

回调需验签/可信身份校验、核对商户、订单、金额币种、交易状态，事务内幂等记支付事件并授予权益；响应丢失重试不重复发赠月。定期主动查单、每日账单核对，处理已扣款未到账、订单超时后成功和重复购买。一个家庭已有买断时前端阻止重复购买，后端并发兜底并提供退款处理。

售后页提供订单、到账、AI 激活与使用、退款申请。是否可退按适用法律、平台规则和清楚展示的服务协议处理，不写“一经使用概不退款”。退款完成后按订单来源撤销相关权益；不得撤销另一个已付订单的权益。全额退核心订单时同步处理赠送 AI，已另购 AI 的未履行部分提供单独退款/解决路径，不让用户失去使用前提却仍扣服务费；数据只读导出仍保留。退款事件和补单都可审计。

### 10.5 购买引导【变更】

用“解锁核心产品”和“续购 AI 服务”两种清楚入口替代原混合会员漏斗；AI 到期、余额不足时轻提示，不打断基础任务。删除简报打码、孕晚期焦虑促销与 3—5% 转化目标；爸爸报告分享页可有普通产品介绍，但不泄露家庭资料。

### 11.1 估算假设

两人均具备全栈经验、每周各约 25—30 小时有效投入时，计划 **20—24 周**；单人同等周投入约 **28—32 周**。专业内容审校为独立资源，应从 W1 联系；如果没有审校能力，先上线非医疗事务与受限知识，公开生成式健康回答保持关闭。审批/登记/平台审核等待是外部依赖，不承诺固定上线日。

## 16. 附录：App 阶段的分发方案（GitHub Releases + Pages）

> 【保留并修正】二期 App/可能桌面端的候选分发方式，不属于小程序一期交付。GitHub 可作为开发者与海外分发基础，不承诺正式国内渠道零成本。

### 16.1 三部分组合

| 部分 | 做法与约束 |
|---|---|
| 安装包托管 | GitHub Releases，tag 对应明确提交，上传 APK/DMG/EXE 等产物；每个 asset 必须小于 2 GiB，不能写“2GB 均可” [S5] |
| 下载展示 | GitHub Pages 放静态说明页，按钮指向 Release；遵守 Pages 对站点用途与资源的限制，正式商业下载页优先独立托管 [S6] |
| 自动化 | GitHub Actions 在 tag 触发测试、构建、签名、制品校验、发布；正式 release 由维护者确认产物来源与版本 |

### 16.2 发版细节

最新版链接模板保留：`https://github.com/用户名/仓库/releases/latest/download/包名.apk`。asset 名称要稳定，草稿/预发布不当正式最新版；记录 SHA-256、版本号、最低支持版本、更新说明与构建来源。

命令示例保留：`gh release create v1.0.0 ./app-release.apk --title "v1.0.0" --notes "首个正式版本"`。只作为以后工程操作示例，不表示本次已发布。

安装包不放源码 Git 历史，避免仓库单文件/体积限制。Pages 当前文档列发布站点 1GB、每月 100GB 带宽软限制等，实际方案以当时规则为准 [S6]；不能把这些配额当长期商业 SLA。

签名密钥存安全环境，Actions 最小权限；Android 签名连续性、macOS 签名与公证、Windows 签名与安全提示按平台处理。更新包校验签名/摘要、禁止降级到已知危险版本，保留回滚与用户数据兼容策略；桌面不是一期必做项。

### 16.3 国内与 iOS 适配

国内访问 GitHub 稳定性作为实测风险；主渠道优先国内合规应用商店、可访问官网/对象存储与 CDN，GitHub 为开发者/海外备选。官网、CDN、证书、域名、流量、商店材料可能产生费用，不宣称“零成本正式分发”。

iOS 正式面向普通用户以 App Store 为主要候选；TestFlight 用于测试，企业分发与地区例外各有限制，GitHub Release 不能代替签名与平台资格。删除旧版“iOS 只能 App Store”的绝对描述，具体按目标地区和当时规则核对。

国内 App 备案、网站 ICP、商店资质按主体与部署实际处理，不将 App 备案与 ICP 简单视为同一事项，不承诺 2—4 周办完。启动 App 时同步核查账号、隐私清单、儿童信息规则、推送与支付渠道。跨端账号与权益映射需防账号误绑，商店支付政策重新审核，不能假设小程序购入权益展示方式在各商店均自动获准。

- [S1：国家网信办 2026 年 7—8 月生成式 AI 服务备案/应用登记公告](https://www.cac.gov.cn/2026-09/14/c_1791136833136332.htm)：区分模型服务备案与直接调用已备案模型的应用/功能登记。
- [S2：《人工智能生成合成内容标识办法》答记者问](https://www.cac.gov.cn/2025-03/14/c_1743654685896173.htm)及[办法正文](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)：核对标识、导出与协议要求。
- [S3：《中华人民共和国个人信息保护法》正式文本（工信部转载）](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html)：敏感信息单独同意、儿童信息、撤回与影响评估等。
- [S4：NICE 关于早孕与流产的正式建议](https://www.nice.org.uk/guidance/NG126/chapter/diagnosis-of-viable-intrauterine-pregnancy-and-of-tubal-ectopic-pregnancy)：末次月经不能单独保证孕龄准确；仅作为日期来源管理的设计参考，不移植为国内诊疗排程。
- [S5：GitHub Releases 官方文档](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)：制品分发与文件上限。
- [S6：GitHub Pages 官方限制](https://docs.github.com/en/enterprise-cloud%40latest/pages/getting-started-with-github-pages/github-pages-limits)：资源和用途限制。

**仍需在对应里程碑锁定的外部事项：**具体模型/API 与报价、专业审校人、当地内容来源、平台类目与支付支持、登记/备案适用性、法定保留期限。它们不阻塞非医疗核心自用开发；未完成时对应公开 AI、支付或数据处理功能不得开启。所有内部规则以本版为开发基线，变更须更新版本及购买/授权告知。
