# 自动周简报、提醒与分享

本轮完成软件功能及合成验收；按用户要求，真机和支付渠道验收暂缓。微信订阅发送为可配置的可选链路，默认关闭，本轮没有发送真实消息。

## 自动周简报

服务端调度器按家庭 IANA 时区，在周一 08:00 起整理本周，未在该时刻运行时可在同周补齐；不补建已经过去的周。每位当前有效成员有独立快照，普通成员只含自己有权查看的分工。可在“自动周简报”主动重新整理本周，安静状态不生成促活卡。

简报冻结生成时的完成事实、最多三件当前周事项和当时有效的生活知识引用。普通任务后来完成，不把过去快照改成今天的数据；实时“每周爸爸报告”仍按当前记录重算，两者在界面明确区分。历史简报可读取生成时的记录和完成明细。

每次读取或投递都复核成员、角色、当前可见事项、健康/独立宝宝授权、日期背景、引用发布版本和有效期。收回授权时立即清理对应接收人的旧内容，重新授予也不让旧正文自行复活；本周下次调度可重建新修订。日期、可见宝宝状态、成员变化或知识下架导致失效时，移除旧正文而非交付过时的敏感内容。

同一家庭、接收人、周只有一个当前快照；重建增加修订号，事务和请求号共同防止并发重复。每人只能读取自己的快照，统筹角色不允许打开他人的历史。站内周报提醒默认关闭，可单独开启；简报本身仍自动整理、完整可见。

当前使用确定性静态简报，不调用模型、不占 AI 配额、不自动创建检查或预约。没有把“AI 未配置”当作自动简报不可用的理由；静态路径始终独立。第二十一轮增加的可选增强见 [生活任务库与 AI 增强](生活任务库与AI增强.md)，需要单独同意。

## 提醒偏好与队列

| 设置 | 默认 | 范围/含义 |
|---|---|---|
| 任务、预约、确认请求 | 开启 | 每人独立，可分别关闭 |
| 周报提醒 | 关闭 | 开启后提示已有自动简报，未开启仍可主动查看 |
| 静默 | 关闭，预填 22:00—08:00 | 支持跨午夜，按家庭时区执行 |
| 每日上限 | 20 | 1—50 条消息，已合并的一组算一条 |
| 合并同类提醒 | 关闭，每组 5 项 | 开启后每组 1—20 项，只合并同一接收人和类型 |
| 预约提前天数 | 3 | 0—14 天，最多 4 个不重复值，如 3、1、0 |
| 任务提前天数 | 1 | 0—7 天，最多 4 个不重复值，如 1、0 |
| 微信订阅 | 关闭 | 另需明确配置和逐次平台授权 |

首次进入一个提醒窗口可整理该窗口；多个提前点都已过去时只采用最近的有效窗口，尚未投递的较早窗口会被取代。静默或达到每日上限时保留待发送；实际日期已过、来源更改、暂停、离开家庭或权限失效时取消/过期，不恢复后堆积补发。安排改期与重开使用修订号，原未读提醒和旧待确认入口同步撤销。

站内队列状态为 scheduled/sent/cancelled/expired，sent 仅表示通知在同一数据库事务中写入，不能解释成外部送达。合并通知逐一核验每个来源；某个来源撤权后不会通过合并数量泄露私密事项。已有旧版通知 ID 不覆盖成新未读，也不在升级时重新提醒一次。

账号、邀请与协作变更仍作为站内操作记录保留，不属于主动提醒，且不借这些记录向外发送。提醒不是医疗预警或急救渠道。

## 可选微信订阅链路

服务端进程配置参考 `.env.example`，程序不自动读取 `.env`：

```text
WX_NOTIFY_ENABLED=0
WX_APP_ID=
WX_APP_SECRET=
WX_REMINDER_TEMPLATE_ID=
```

只有显式启用 `WX_NOTIFY_ENABLED=1` 并提供 AppID、密钥与已审核的普通提醒模板，客户端才展示可用订阅入口。模板需支持 `thing1` 文字字段，固定内容为“你有待查看事项”，跳转仅到 `pages/main/main`。不发送家庭名称、孕周、诊疗、结果、日期、令牌或实际任务标题；实际部署还需允许 HTTPS 访问微信服务。

小程序通过本人点击逐次调用 `wx.requestSubscribeMessage`，拒绝或取消不会登记资格。服务端把本次声明绑定到通过微信 code 验证的**准确身份 ID、用户、家庭、AppID 和模板**，不是随便取同账号曾绑定的第一个 openid。客户端迟到回调、退出或切换账号后不提交旧同意；绑定返回前服务端也重新核验当前会话。

本地保存的是一次授权声明，不假装它已经被平台认证。声明最多使用一次，7 天未用失效；实际平台仍会核验资格。发送前再次核对当前开关、静默、每日上限、成员、来源与授权；读过站内消息后不再额外打扰。关闭外部开关或成员范围变化会撤销未使用声明，不能关掉再打开就复活旧资格。

网络操作在数据库事务外执行，发送前以事务占用资格并建立唯一投递记录。多 worker 不能重复消费同一声明。每条站内消息最多发起一次外部发送：

- 取访问凭证失败：没有发出消息，不消耗声明；保留站内事项。
- 平台明确返回 0：记录平台接受请求，不宣称已送达设备或已读；若有消息 ID 则保留真实回执，不编造。
- 平台明确拒绝：记录 failed 与真实错误码，不能记作成功。
- 网络超时、响应无法判断或进程中断：标记 unknown，不自动重发；继续以站内待办为准。

外部发送另受同一每日上限约束，未知请求也占用当天尝试额度。凭证只在内存缓存，日志不输出密钥、请求令牌或完整错误 URL。账号删除期间的迟到响应不能重建该账号的投递记录。真实模板匹配、平台许可和真机送达留待用户恢复真机验收时检查；本轮仅使用模拟响应验证。

## 通用与私密分享

默认通用模板：网页 `/#template`、小程序固定 `pages/main/main?template=1`。只有通用生活物品与核对说明，不含家庭名称、成员、健康日期、实际完成比例，也不会自动加入家庭。系统分享回调始终使用这个公开路径，即使当时正在查看私密清单或徽章。

统筹者可选择 1—50 个物品，明确确认后生成 1—168 小时（默认 24 小时）的私密链接。快照仅包含选定的名称、分类、数量、优先级和准备状态，另外给出链接有效期；不含备注、负责人、家庭名称、孕产日期、徽章或邀请权限。物品名称本身仍可能私密，创建前必须确认。

私密令牌为随机 256 位值，经 URL fragment 传递，网页用 JSON POST 读取，不把令牌放在服务器请求 URL。分享记录只保存令牌哈希；原令牌在创建/同请求恢复结果中返回，恢复结果受私有命令账本保护，不能公开数据库或记录响应体。分享管理不返回原令牌。

匿名读取每次校验有效期、撤销状态、创建者当前统筹权限、家庭成员范围、家庭版本和所选物品版本。内容或范围变化使旧链接失效，不自动向旧接收人透露后续修改；成员退出再加入也不会复活旧链接。无效、过期与撤销使用一致的不可用响应，失败读取也消耗限流额度。

创建丢响应时用原请求号取回原链接，不重复新建；恢复结果已失效则明确提示重新选择，不展示成新有效链接。撤销清空快照内容，过期由调度器清理。分享页刷新或返回前台会重新读取并清理失效内容，但已经截图、复制或保存的内容无法追回。

## 删除、恢复与接口

删除账号清理参与记录、关联完成证据、分享、简报及投递衍生数据。恢复备份不会复活旧会话、分享令牌、订阅资格或待发送记录；保留仍属本人且授权有效的历史简报，清理已撤回共享授权对应的快照。

| 接口/动作 | 用途 |
|---|---|
| GET `/api/briefings`、`/api/briefing` | 当前成员本人的历史快照与读取校验 |
| `briefing.refresh` | 主动重新整理本周 |
| `engagement.checkin/preferences/support` | 当天参与、个人安静偏好、本人陪同声明 |
| `notification.preferences/subscribe` | 分类/静默/合并设置、本次平台订阅声明 |
| GET `/api/notification-options` | 返回订阅是否配置及公开模板 ID，不返回凭证 |
| `share.create/revoke` | 选择并确认私密快照、撤销 |
| GET `/api/public/template` | 无账号的通用模板 |
| POST `/api/shared` | 无会话的令牌读取，仍逐次校验分享范围 |

动作通过现有 `/api/action` 提交，继续使用内容绑定请求号和当前成员鉴权。家庭 ID 参数只用于登录后的接口；公开分享不能靠可枚举家庭 ID 读取。响应禁止缓存。
