# 重复家务任务

网页/App 共用页面和微信小程序现在可创建按天或按周重复的普通家务。每次安排生成独立任务，可单独改期、分工、完成或跳过，沿用现有权限、版本检查和妈妈二次确认。

## 使用方式

1. 在行动清单新建任务，填写名称、负责人和日期。
2. 选择“按天重复”或“按周重复”，填写 1—30 的间隔；日期即首次日期，不能早于家庭时区的今天。
3. 结束日期可不填；填写时包含截止当天，不能早于首次日期。
4. 在“重复家务安排”查看、修改后续规则，或暂停/恢复安排。停止会取消未完成实例且不能重新启用；完成和跳过的历史不变。

例如，首次日期为周三，选择每 2 周重复，后续日期仍是隔周的周三；不是在每次完成后再加 14 天。按天重复以当地日历日期递增，不按 24 小时秒数推算，不因夏令时漂移。

重复家务独立于孕次时间轴，不根据孕周自动安排医疗行为。妊娠结束、分娩或归档不会自动取消用户明确建立的普通家务；需要停止时使用重复安排入口，普通任务提醒开关仍然有效。医疗事项应使用已确认预约，不能把重复家务当作医护日程。

## 生成与历史

- 创建时生成家庭时区今天至未来第 14 天以内的实例，包含两端。每天一次且没有结束日期时，初次最多生成 15 条。
- 服务端现有调度器每约 30 秒滚动补齐窗口；首次日期更远时先保存规则，进入窗口后才出现实例。完成本次任务不是生成下次任务的条件。
- 每个实例以规则 ID 和原定日期确定唯一 ID。网络重试、并发调度或单次改期均不会为原定日期再建一个实例。
- 每个实例可单独改名、改期、分配或更新说明，修改只影响本次；后续仍按原规则生成。改期后原定日期保留在 `series_date`。
- 停机期间没有生成过的过往日期不补建，避免恢复后堆积大量过期事项；停机前已经生成的实例和完成历史会保留。
- 到结束日期之后，规则标记为“已到结束日期”，不继续生成；此前未完成的记录不会被系统伪装成完成。

## 修改后续规则

统筹者可修改标题、说明、负责人、日/周周期、间隔、首次日期和结束日期。修改从家庭时区的今天生效，只重排今天起尚未开始的自动实例：

- 已完成、已跳过、过去日期、进行中、待确认及单独编辑过的实例保留原内容、日期、负责人、版本和确认。
- 单次编辑说明、标题、负责人或日期会标记为独立调整；旧客户端已经改过内容的实例也会保留，不要求补写标记。
- 仍在新周期内的自动实例复用原定日期的 ID 并更新内容；不再匹配的自动实例取消并成为只读，相关旧未读提醒撤销。
- 被规则调整取消的自动实例，如果后续规则又包含该日期，可以复用原 ID 恢复；用户手动取消、已完成、跳过或过期的实例不会因此重新出现。
- 保留原首次日期时允许它位于过去，以保持原来的日历周期；若改首次日期，须选择家庭今天或以后。结束日期仍包含当天，可以清除。已到结束日期的规则可通过延长/清除结束日期继续安排；已停止规则不可修改或重启。
- 修改会增加规则修订号并保存前后规则与影响数量的审计。未改任何字段时不增加版本、不重新提醒。暂停中的规则修改后仍暂停。

当前支持日、周两种周期，不提供月度重复。

## 暂停与恢复

暂停会停止新增，将所有未完成实例标记为已暂停且只读，撤销旧未读提醒和待确认申请；已完成、已跳过和手动取消记录不变。进行中实例的原执行状态会保留用于恢复，待确认实例按进行中保存，不保留可批准的旧确认。

恢复只启用尚未过期的暂停实例并补齐今天到未来第 14 天的窗口。已过日期继续关闭，不补建暂停期间错过的任务；单次改到未来日期的实例按实际日期判断，未设日期的单次实例也可恢复。旧待确认实例回到进行中，需要执行人重新提交确认。若已过规则结束日期，先修改规则延长/清除结束日期再恢复。

规则修改后被关闭、因成员离开而关闭或已停止的实例不会借恢复暂停重新启用。恢复不会生成同一原定日期的重复任务。

## 停止、成员和确认

只有当前统筹者可新建、修改、暂停、恢复与停止重复安排。其他成员只能提交自己负责实例的结果；基础家人只看到分配给自己的规则和实例，妈妈的普通家庭查看范围沿用现有规则。

停止操作在一个事务内取消所有未完成实例，使相关待确认申请失效，并取消未读任务提醒和仍待处理的确认提醒。随安排停止的实例成为只读记录，不能再完成、编辑或恢复；停止不会改动已完成、已跳过的状态与原日期。已完成记录若需要纠正，仍按原有单次任务操作权限处理，不会重新启用整组重复。

负责人退出、被移出家庭或删除账号时，对应规则也停止，未完成实例取消。重新加入不会自动恢复旧规则。删除重放的备份恢复同样执行停止，避免恢复后继续给已删除的账号安排任务。不会猜测另一位家人接任。修改规则后保留下来的旧负责人实例，如该负责人离开，会关闭这些实例并使其确认失效，但不会停止已交给有效新负责人的后续规则。

每种操作继续使用内容绑定的请求号；网页和小程序沿用第十三轮的弱网核对入口。修改、暂停、恢复和停止均使用规则版本，旧页面或其他家庭的规则 ID 会被拒绝；编辑表单保留打开时的版本，不用刷新后的新版本覆盖他人的修改。

## 接口与数据

重复规则仍由 `POST /api/action` 提交，`action` 为 `task.create`：

```json
{
  "title": "整理厨房",
  "note": "按实际精力安排",
  "assignee": "同家庭的有效成员 ID",
  "due_date": "2026-10-28",
  "repeat": "daily",
  "repeat_every": 2,
  "repeat_until": "2026-11-11"
}
```

`repeat` 可为 `daily`、`weekly`；`repeat_every` 必须为整数，不能用布尔值代替。普通单次任务不填 `repeat` 或填写 `none`。`repeat_until` 可为空。

返回包含 `series_id` 和初次生成数 `created_occurrences`。停止使用 `action: task_series.stop`，参数为规则的 `id`、`version`；返回本次新取消数 `cancelled_occurrences`。重复停止不重复写历史或生成实例。

`task_series.update` 携带规则 `id`、`version` 和与创建一致的编辑字段（`title`、`note`、`assignee`、`repeat`、`repeat_every`、`due_date`、`repeat_until`）；省略字段保留原值，结束日期传 `null` 清除。返回更新、取消、新增及保留实例数。`task_series.pause`、`task_series.resume` 携带 `id`、`version`，分别返回暂停数量、恢复数量与新增数量。同状态重复操作不改写记录；网络重放仍按原请求号处理。

状态与当前可见数据导出包含 `task_series`；任务增加 `series_id`、`series_date`，停止的实例带 `series_stopped`；暂停/规则变更/错过暂停窗口/旧负责人离开时，分别用 `series_locked` 的 `paused`、`rule_changed`、`pause_elapsed`、`assignee_inactive` 区分只读原因。实例还保留 `series_revision`，单次修改用 `series_override` 标记；均沿用原表，无需迁移旧数据。状态还返回公开的家庭 `calendar_date`，小程序不需要从妈妈的私密时间轴猜测今天。数据继续保存在原有 `records` 表，不新增外部服务或迁移旧普通任务。
